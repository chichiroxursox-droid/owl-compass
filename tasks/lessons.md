# Lessons — Owl Compass

- **Test the path the user actually takes.** The first-draft screenshot check only clicked the example-goal links, so typing a goal and then adjusting skills was never exercised, and that is where it broke. End-to-end checks should type into the real input, submit it, then change the other controls.
- **A typed goal must rank results itself.** v1 turned the goal into skill weights and ranked only by those, so the goal disappeared once the student touched the skills, and "AI" never matched courses about AI. Keep the student's own intent as its own signal (`fit` from `/api/interpret`). Controls like the skills should refine it, not replace it.
- **Catalogs repeat courses.** 265 of 482 codes are cross-listed or Honors copies of another (one course has 7 codes). Collapse copies before taking a top-N, or a single course fills an area. A title alone isn't a safe key, for two reasons. "World Society in Literature & Film" is a different culture in each department, and some Honors copies have their own subtitle. `tools/twins.py` links copies by area and course number, plus either the same title or the same department. Pick which copy to show by its match score, not by Spring/Honors alone, because copies are tagged differently.
- **Read the AI's picks before trusting a prompt.** The first catalog prompt filled its list with upper-level major courses and returned no GenEds for an undeclared student. Splitting the GenEd and major lists fixed it; only reading real outputs showed the problem.
- **Don't use `messages.parse()` with server-side fallbacks.** It parses every text block in the reply, including half-written JSON a model leaves before handing off to the fallback model, and throws. Numeric limits in a zod schema (`min`/`max`, `z.literal([1,2,3])`) never reach the API either, so one out-of-range value fails the whole reply. Ask with `create()`, check only the final text block, clamp numbers in code, and retry once (`app/api/claude.ts`).
- **Measure the model choice, don't assume it.** In a side-by-side test on the same prompt, Haiku 5.5 padded and repeated picks, while Sonnet 5.5 at adaptive `low` effort was precise and only about 0.5 s slower (2.7 s even on a cold 47K-token cache).
